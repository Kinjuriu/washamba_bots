# Endgame Plan — Kaggriculture, Sept 21 → Sept 30, 2026

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. This is a research campaign, not a feature: every task ends in a **measured gate**, and a task whose gate fails is *closed*, not patched.

**Goal:** Put two submissions into the Sept 30 freeze that finish top-10 in the Oct 1–15 Bradley-Terry cooldown tournament (the $5,000 prize line; #1 is the stretch).

**Architecture:** The final tournament is played against a *frozen* field, which removes the two things that killed our rank-16 agent on Aug 31 (self-eviction and same-day copying). So the plan is (1) a deterministic **replay-the-ladder harness** that reproduces our real episodes to the dollar and becomes the only local test we trust; (2) a **cash-aware repair layer** on our best tape router so critical purchases stop failing silently under contested cash; (3) a **late harvest** of the strongest *copyable* top-10 schedule, rebuilt as a router with our sell-advance rim; (4) a **submission protocol** that uses the 5 daily slots as ladder experiments all week and lands the final pair in the right order.

**Tech Stack:** Python 3.13 in `.venv/` (`.venv/Scripts/python.exe`), `kaggle-environments>=1.32.6`, stdlib `unittest`, Kaggle CLI (`.venv/Scripts/kaggle.exe`), existing tooling in `experiments/tapes/` and `experiments/ladder_episodes.py`.

## Global Constraints

- **Deadline:** final submission Sept 30, 2026 (assume 23:59 UTC — not pinned to an hour in our docs; treat 20:00 UTC as the last safe submit). Cooldown Oct 1 – ~Oct 15. 5 submissions/day; only the **latest 2** are active; eviction drops the **oldest**.
- **Rate limits:** `ListEpisodes` returns 429 after ~19 calls and stays blocked for hours. **Exactly one agent owns that endpoint per wave, with a written call budget.** Replay downloads (`kaggleusercontent.com/episodes/{id}.json`, ~10s each, ~31 MB) are a separate limit and may run in parallel threads (≤6).
- **Kaggle submit commands are classifier-blocked for Claude.** Peter runs them with `!`. Every submit must first pass the gate: `env.run(['<file>','<file>'])` on seed 0 → `['DONE','DONE']` and neither reward == 3000.
- **Replays and pulled kernels are never committed.** Cache under `experiments/endgame/rep/` and `experiments/endgame/kernels/` (both gitignored).
- **Read win counts before means; read per-episode ladder records, never the public score alone** (`experiments/ladder_episodes.py`). Compare submissions only at equal n *and* opponent field within 150 rating points.
- **Any harvested tape's origin is recorded** (episode id, team, submission id) in the agent file header. Keep the Apache 2.0 attribution on anything derived from the yhay81 router. Winner obligation is a CC-BY methodology writeup — public replays and public notebooks are fine under it.
- Engine RNG is keyed off `env.info["seed"]` + day (`kaggriculture.py:869`), hires spawn on a shed-access tile (`_spawn_hand`, line 533), market orders settle in list-index lockstep, `money < price` drops an order silently (`_commit_unit`).
- Model routing: Fable/Opus for design, diagnosis and any gate that disagrees with expectation; Sonnet for harvest/harness/inventory implementation; Haiku for nothing here.

## Honest odds (stated once)

Top-10 needs both (a) a copyable schedule at or near today's top and (b) our tape no longer collapsing when the market path diverges. If both land: roughly one in five for a prize seat. If today's top 10 is all reactive (as #1 was on Sept 1) the harvest leg is dead and it's the repair leg alone — top-100 likely, top-10 under 5%. Nothing in this plan changes those numbers by being written down; only the gates do.

### Task T5: Cash-aware repair layer (after T3 gate)

**Files:**
- Create: `agents/router_yuan_nf_trim_cf.py` (base: `router_yuan_nf_trim.py`, or `ar2` if T1 reads better) — "cf" = cash floor.
- Test: `tests/test_router_cf.py`

**The two measured traps, do not repeat:** reordering a `SELL` behind a `BUY_ANIMAL` is −30k (the sell funds the buy); deferring `BUY_SEED` is −30k+ (desyncs the scripted `PLANT`, engine drops the planting). See `agents/router_yuan_nf_trim_ar.py` header.

**Approach that avoids both:** never move or delay a recorded order. Instead:
1. **Sell-to-fund.** Pre-scan the active tape for critical buys (`BUY_ANIMAL`, `BUY_LAND`, `BUY_PRODUCT WHEAT` when shed wheat < animals). Within 24 steps before one, project cash = money + backed recorded sells − recorded buys. If projected < price + $50, **prepend** an extra `SELL` of held non-wheat, non-fertilizer product (largest stock first, capped at the shortfall / current price) at index 0. This adds an order; it moves nothing.
2. **Retry with carriage.** If a `BUY_ANIMAL` still fails (detect next step: shed animal count unchanged), re-issue it at the first later step where money ≥ price, then hire one extra hand that step (it spawns on a shed-access tile), and script that hand: `PICKUP <animal>` → walk to the empty pasture → `PLACE`. Hands vanish nightly, so this desyncs nothing in the tape.
3. Nothing else changes. Byte-identical actions when no critical buy is at risk.
